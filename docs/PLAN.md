# منصة البطولات الكروية — خطة المرحلتين

Nov 22, 2026 · @جمعية الميثاق الاعظم

## الخلاصة

يُقسَّم المشروع إلى مرحلتين: **المرحلة الأولى** موقع إلكتروني وتطبيق جوال لإدارة البطولات الشعبية والنتائج والرعاة دون أي بث مباشر (8–11 أسبوعاً تقريباً)، و**المرحلة الثانية** تضيف البث المباشر و«المدرسة العراقية لتطوير المهارات الكروية» لتطوير لاعبي الفرق الشعبية (9–12 أسبوعاً تقريباً).

|  | المرحلة الأولى | المرحلة الثانية |
| --- | --- | --- |
| الهدف | إطلاق سريع واختبار الطلب وجذب الرعاة | التوسع وزيادة القيمة والإيرادات |
| المنصات | موقع + تطبيق + لوحة إدارة | نفس المنصات مع وحدات جديدة |
| الوحدات | الحسابات، التوثيق، البطولات، الفرق، اللاعبون، المباريات، النتائج، الاعتراضات، الأخبار، الهيرو سلايدر، الرعاة | البث المباشر، الإعادات والمقاطع، المدرسة العراقية لتطوير المهارات الكروية، ترشيح المواهب من البطولات |
| ما يُستبعد | البث، المدرسة | — |

## نتائج تحليل الملف

الملف سليم في ضوابطه، لكن البث متداخل في أربعة مواضع يجب فصلها، وتنقصه جداول البطولات نفسها وهي أساس المرحلة الأولى.

**مواضع البث التي تُؤجَّل:**

| الموضع في الملف | التعديل في المرحلة الأولى |
| --- | --- |
| الهيرو سلايدر: «شريحة المباراة المباشرة» التلقائية | تُستبدل بشريحة «مباراة اليوم» أو «نتيجة مباشرة» تُحدَّث نصياً من الحكم |
| مصفوفة الأدوار: عمود «البث» و«تراكب الرعاة» | يُحذف العمود الآن ويُضاف في المرحلة الثانية |
| جدول `live_streams` وحقل `minors_consent_verified` | لا يُنشأ الآن؛ لكن موافقة التصوير للقاصرين تبقى (للصور) |
| خارطة التنفيذ: المرحلة 3 البث والمرحلة 4 المدرسة | تُنقلان معاً إلى المرحلة الثانية |

**نواقص وجدتها في الملف:**

1. **لا توجد جداول للبطولات والفرق والمباريات والنتائج** في القسم 4، مع أنها قلب المشروع. أضفتها في المرحلة الأولى أدناه.
2. **اللاعبون القاصرون في البطولات:** الملف ربط ولي الأمر بمتدربي المدرسة فقط. البطولات الشعبية فيها لاعبون دون 18 أيضاً، فيجب تطبيق القاعدة نفسها من المرحلة الأولى.
3. **المدرسة مصممة للأطفال فقط** (فئات تحت 8 إلى 18 وولي أمر إلزامي). المدرسة العراقية لتطوير المهارات الكروية ستضم بالغين أيضاً، فيحتاج التصميم إلى مسارين: بالغ يسجل بنفسه، وقاصر عبر ولي أمره.
4. **سجل التدقيق:** الـ Trigger لا يمنع `TRUNCATE` (يعتمد على سحب الصلاحية فقط). أضف Trigger من نوع `BEFORE TRUNCATE ... FOR EACH STATEMENT` لحماية أقوى.
5. **جدول `slide_events`** سيكبر بسرعة بلا فهرس. أضف فهرساً على `(slide_id, created_at)` وقيداً يمنع تكرار الظهور لنفس الجهاز في اليوم الواحد.
6. **الموقع غير مذكور:** الملف يتحدث عن Flutter ولوحة إدارة فقط. أضفت الموقع العام ودوره أدناه.

## المرحلة الأولى: الموقع والتطبيق (بدون بث)

تُبنى خلفية واحدة (API وقاعدة PostgreSQL) تخدم الموقع والتطبيق ولوحة الإدارة معاً، فلا يُكتب شيء مرتين.

### توزيع الأدوار بين المنصات

| المنصة | الجمهور | ما تقدمه |
| --- | --- | --- |
| الموقع العام | الجمهور، الرعاة المحتملون، محركات البحث | البطولات والجداول والنتائج والترتيب، الأخبار، صفحة «كن راعياً»، رابط تحميل التطبيق، الشروط والخصوصية |
| التطبيق (React Native / Expo) | مدراء الفرق، اللاعبون، الحكام، المتابعون | الهيرو سلايدر، تسجيل الفرق، إدخال النتيجة وتأكيدها، الاعتراض، إشعارات المباريات |
| لوحة الإدارة (ويب) | فريق المشروع | المحتوى، الشرائح، الرعاة وتقاريرهم، البطولات، المستخدمون، سجل التدقيق |

### الوحدات المشمولة

1. **الحسابات والأدوار:** توثيق الهاتف بـ OTP مع Rate Limit، وTOTP للإدارة، وحساب ولي أمر لكل لاعب دون 18.
2. **توثيق صفحات الفرق:** Facebook OAuth مع المسار اليدوي البديل (ابدأ باليدوي إن تأخرت مراجعة ميتا).
3. **البطولات:** إنشاء البطولة، تسجيل الفرق واللاعبين، القرعة، جدول المباريات، الترتيب التلقائي.
4. **النتائج:** الحكم يسجل ويرفق صورة ورقة المباراة، مديرا الفريقين يؤكدان، والحالات: مؤقتة ← معتمدة ← متنازع عليها ← نهائية.
5. **الاعتراضات:** نافذة قابلة للضبط (الافتراضي 24 ساعة) ولجنة انضباط من 3 أشخاص.
6. **سجل التدقيق** بتسلسل التجزئة كما في الملف الأصلي.
7. **الهيرو سلايدر والرعاة:** كما في الملف، مع استبدال الشريحة المباشرة بشريحة «مباراة اليوم» تعرض النتيجة النصية وتتحدث كل 30 ثانية.
8. **المحتوى (CMS):** الأخبار، الصفحات الثابتة، الإشعارات، مكتبة الوسائط، بدورة مسودة ← مراجعة ← منشور ← مؤرشف.

### مصفوفة الأدوار للمرحلة الأولى

| الدور | المحتوى والسلايدر | المباريات والنتائج | الرعاة والمالية | المستخدمون |
| --- | --- | --- | --- | --- |
| مدير عام | نعم | نعم | نعم | نعم |
| محرر محتوى | مسودة ومراجعة | لا | لا | لا |
| مدير الرعاة | شرائح الرعاة فقط | لا | نعم | لا |
| مدير البطولة | لا | نعم | لا | لا |
| الحكم | لا | إدخال النتيجة فقط | لا | لا |
| مدير فريق | صفحة فريقه | تأكيد أو اعتراض | لا | لاعبو فريقه |
| لجنة الانضباط | لا | البت في الاعتراضات | لا | لا |
| الراعي (بوابة) | لا | لا | عرض تقاريره فقط | لا |

### الجداول الناقصة التي تُضاف

```sql
-- البطولات
CREATE TABLE tournaments (
  id                 BIGSERIAL PRIMARY KEY,
  name_ar            TEXT NOT NULL,
  city               TEXT,
  starts_on          DATE,
  ends_on            DATE,
  format             TEXT NOT NULL CHECK (format IN ('league','knockout','groups_knockout')),
  dispute_window_hrs INT  NOT NULL DEFAULT 24,   -- نافذة الاعتراض لكل بطولة
  status             TEXT NOT NULL DEFAULT 'draft' CHECK (status IN ('draft','registration','running','finished'))
);

-- الفرق الشعبية
CREATE TABLE teams (
  id               BIGSERIAL PRIMARY KEY,
  name_ar          TEXT NOT NULL,
  manager_user_id  BIGINT NOT NULL,
  fb_page_id       TEXT,
  verified_at      TIMESTAMPTZ,                  -- تاريخ توثيق الصفحة
  verify_method    TEXT CHECK (verify_method IN ('oauth','manual'))
);

-- اللاعبون (بالغون وقاصرون)
CREATE TABLE players (
  id             BIGSERIAL PRIMARY KEY,
  user_id        BIGINT,                         -- للبالغ
  guardian_id    BIGINT,                         -- للقاصر
  first_name     TEXT NOT NULL,
  birth_year     INT  NOT NULL,
  media_consent  BOOLEAN NOT NULL DEFAULT false,
  CHECK (user_id IS NOT NULL OR guardian_id IS NOT NULL)
);

CREATE TABLE team_players (
  team_id    BIGINT NOT NULL REFERENCES teams(id),
  player_id  BIGINT NOT NULL REFERENCES players(id),
  shirt_no   INT,
  PRIMARY KEY (team_id, player_id)
);

-- المباريات والنتائج
CREATE TABLE matches (
  id              BIGSERIAL PRIMARY KEY,
  tournament_id   BIGINT NOT NULL REFERENCES tournaments(id),
  home_team_id    BIGINT NOT NULL REFERENCES teams(id),
  away_team_id    BIGINT NOT NULL REFERENCES teams(id),
  kickoff_at      TIMESTAMPTZ,
  venue           TEXT,
  referee_user_id BIGINT,
  home_score      INT,
  away_score      INT,
  result_status   TEXT NOT NULL DEFAULT 'scheduled' CHECK (result_status IN
                    ('scheduled','provisional','confirmed','disputed','final')),
  sheet_photo_url TEXT,                          -- صورة ورقة المباراة
  home_confirmed  BOOLEAN NOT NULL DEFAULT false,
  away_confirmed  BOOLEAN NOT NULL DEFAULT false,
  CHECK (home_team_id <> away_team_id)
);

CREATE TABLE disputes (
  id          BIGSERIAL PRIMARY KEY,
  match_id    BIGINT NOT NULL REFERENCES matches(id),
  raised_by   BIGINT NOT NULL,
  reason      TEXT NOT NULL,
  status      TEXT NOT NULL DEFAULT 'open' CHECK (status IN ('open','upheld','rejected')),
  decided_at  TIMESTAMPTZ
);
```

جداول الرعاة والهيرو سلايدر وسجل التدقيق تُؤخذ كما هي من الملف الأصلي، وجداول `guardians` تُنشأ الآن لأن اللاعبين القاصرين يحتاجونها.

## المرحلة الثانية: البث المباشر والمدرسة العراقية لتطوير المهارات الكروية

تُضاف وحدتان فوق أساس المرحلة الأولى، وترتبطان ببعضهما: مقاطع البث تغذي ملف تطوير اللاعب في المدرسة.

### أولاً: البث المباشر

يبقى كما في الملف الأصلي (القسم 3.2)، ويُنفَّذ على خطوتين:

1. **تضمين بث يوتيوب أو فيسبوك** (الخيار أ) لأول بطولة منقولة: شارة LIVE، ربط البث بالمباراة، وتحوّل شريحة «مباراة اليوم» إلى شريحة مباشرة تلقائياً.
2. **خدمة بث مُدارة** (الخيار ب) عند نمو الجمهور: بث تكيّفي و360p افتراضي، إعادات ومقاطع أبرز، وتراكب شعار الراعي.

يُضاف هنا جدول `live_streams` وعمود «البث» في مصفوفة الأدوار، ويبقى شرط موافقة ولي الأمر قبل بث أي مباراة فيها قاصر.

### ثانياً: المدرسة العراقية لتطوير المهارات الكروية

الفكرة تتغير عن الملف الأصلي: ليست دليلاً لأكاديميات متعددة للأطفال، بل **مدرسة واحدة باسم موحّد** تطوّر لاعبين موجودين أصلاً في الفرق الشعبية، بالغين وناشئين.

**الميزات:**

- **ترشيح من البطولات:** أداء اللاعب في البطولات (أهداف، أفضل لاعب، تزكية مدير الفريق) يرشحه للمدرسة، والمدرب يقبل أو يرفض.
- **برامج قصيرة:** معسكرات نهاية الأسبوع، دورات مهارات ولياقة، برنامج حراس المرمى، لا اشتراكات شهرية طويلة فقط.
- **تأهيل مدربي الفرق الشعبية:** دورات للمدربين أنفسهم، فالتطوير ينتقل إلى الفريق كله.
- **ملف تطوير اللاعب:** تقييمات دورية (مهارات، لياقة، انضباط)، الحضور، ومقاطع من البث. البالغ يراه بنفسه، والقاصر يراه ولي أمره.
- **منح برعاية:** مقاعد مجانية يمولها الرعاة باسمهم، وتظهر في تقاريرهم.
- **تسجيل ودفع:** زين كاش أو حضورياً، مع سياسة استرجاع واضحة.

**حماية الناشئين:** تبقى قواعد الملف كلها (لا مراسلة خاصة بين بالغ وقاصر، تحقق من خلفية المدربين، اسم أول وصورة بموافقة فقط، «لائق للتدريب» دون تفاصيل طبية)، وتنطبق على مسار الناشئين فقط.

**الاسم:** المدرسة العراقية لتطوير المهارات الكروية. تحقق قبل التسويق من عدم وجود جهة أو علامة مسجلة بالاسم نفسه.

**تعديل الجداول:** تُستبدل `trainees` بجدول `players` من المرحلة الأولى (اللاعب نفسه في البطولة والمدرسة)، وتُضاف:

```sql
-- الترشيح من البطولات
CREATE TABLE academy_nominations (
  id            BIGSERIAL PRIMARY KEY,
  player_id     BIGINT NOT NULL REFERENCES players(id),
  match_id      BIGINT REFERENCES matches(id),
  nominated_by  BIGINT NOT NULL,
  status        TEXT NOT NULL DEFAULT 'pending' CHECK (status IN ('pending','accepted','declined'))
);

-- تقييمات التطوير
CREATE TABLE player_evaluations (
  id           BIGSERIAL PRIMARY KEY,
  player_id    BIGINT NOT NULL REFERENCES players(id),
  coach_id     BIGINT NOT NULL,
  skills       SMALLINT CHECK (skills BETWEEN 1 AND 10),
  fitness      SMALLINT CHECK (fitness BETWEEN 1 AND 10),
  discipline   SMALLINT CHECK (discipline BETWEEN 1 AND 10),
  notes_ar     TEXT,
  evaluated_on DATE NOT NULL DEFAULT current_date
);
```

ويُضاف إلى `academy_programs` حقل `track` (بالغين / ناشئين) وحقل `sponsor_id` للمنح.

## ما نجهزه الآن للمرحلة الثانية

أربعة قرارات صغيرة في المرحلة الأولى تمنع إعادة البناء لاحقاً:

1. **جدول `players` موحّد** للبالغين والقاصرين، حتى يُنقل اللاعب إلى المدرسة بضغطة دون تسجيل جديد.
2. **حقل موافقة الصور `media_consent` يُجمع من اليوم الأول**، ونص الموافقة يذكر البث مستقبلاً، فلا تحتاج لطلب الموافقة من جديد.
3. **`slide_type = 'match'` موجود من الآن** في الهيرو سلايدر، فتتحول شريحة «مباراة اليوم» إلى مباشرة بإضافة رابط بث فقط.
4. **إحصائيات اللاعب في المباراة** (هدف، بطاقة، أفضل لاعب) تُسجّل من المرحلة الأولى؛ هي مصدر ترشيحات المدرسة لاحقاً.

المدد تقديرية لمطور واحد بدوام كامل، وتقل مع فريقك.

| الخطوة | المدة | المحتوى |

| **المرحلة الأولى — 1. الأساس** | 3–4 أسابيع | الحسابات، التوثيق، البطولات، المباريات، النتائج، سجل التدقيق |
| 2. المحتوى والرعاة | 2–3 أسابيع | لوحة الإدارة، الهيرو سلايدر، الرعاة، الأخبار، الإشعارات |

## النشر: GitHub ثم استضافتك الخاصة

المشروع يُرفع على GitHub، ثم يعمل على VPS هوستنجر برابط مؤقت حتى يكتمل، وبعدها يُربط بالدومين المخصص.

1. **GitHub:** مستودع خاص في حسابك `abtkare`، فيه ملف `docker-compose.yml` جاهز في الجذر. GitHub Actions يبني الخادم والموقع ويرفع الصور تلقائياً عند كل رفع، فلا تحتاج لفك أي ملف.
2. **الـ VPS:** من Docker Manager في هوستنجر ← Compose from URL برابط ملف الـ compose. أي خطوة تحتاج أوامر (مثل تسجيل الدخول لسحب الصور الخاصة لمرة واحدة) نكتبها لك نصاً جاهزاً تعطيه لوكيل هوستنجر الذكي.
3. **عزل المشروع:** حاويات وقاعدة بيانات وشبكة خاصة به، على منفذ غير مستخدم، دون لمس «خصوصي» و«مشاوي».
4. **الرابط المؤقت بدون دومين:** استخدم عنواناً مجانياً مبنياً على IP الـ VPS مثل `IP.sslip.io` بدل `http://IP:منفذ` المجرد. السبب: تسجيل دخول فيسبوك وتطبيق الآيفون يشترطان HTTPS، وشهادة HTTPS المجانية تحتاج اسم نطاق.
5. **أثناء التطوير:** منع فهرسة محركات البحث، وحساب تجريبي للإدارة، وقاعدة بيانات تجريبية منفصلة عن الإنتاج.
6. **الربط بالدومين:** سجل A من شركة الدومين إلى IP الـ VPS، ثم تغيير متغير `APP_URL` وإصدار شهادة HTTPS جديدة، وتحديث رابط الخادم في التطبيق وفي إعدادات فيسبوك.

## القرارات المعتمدة

كل القرارات التقنية محسومة بعد اختيار Node.js، ولم يبقَ عليك إلا شراء الدومين ومراجعة المحامي قبل الإطلاق.

| القرار | الاختيار | السبب |
| --- | --- | --- |
| اسم المنصة | **ساحة** (Saha) | الفرق الشعبية تلعب في «الساحات»، اسم قصير وعراقي وسهل الحفظ |
| الخادم | Node.js 22 + NestJS + TypeScript | وحدات منظمة، صلاحيات جاهزة، توثيق API تلقائي (Swagger) |
| قاعدة البيانات | PostgreSQL 16 + Prisma، مع SQL خام لسجل التدقيق | Prisma للسرعة، والـ Triggers تبقى في القاعدة نفسها |
| المهام الخلفية | Redis + BullMQ | OTP وRate Limit والإشعارات والتحقق اليومي من سلسلة التدقيق |
| الموقع ولوحة الإدارة | Next.js 15 تطبيق واحد، واللوحة تحت `/admin` | حاوية واحدة، مكونات مشتركة، ظهور جيد في محركات البحث |
| التطبيق | React Native + Expo (بدل Flutter) | لغة واحدة (TypeScript) في كل المشروع، أنواع بيانات مشتركة، تحديثات دون المتجر |
| المستودع | مستودع واحد (pnpm + Turborepo) | رفع zip واحد يحمل كل شيء |
| الملفات والصور | مجلد على الـ VPS خلف طبقة تخزين قابلة للتحويل إلى S3 | بلا تكلفة الآن، والانتقال لاحقاً بتغيير إعداد |

## الهوية البصرية: «ساحة»

هوية رياضية شعبية بمستوى احترافي: أخضر الملعب للثقة، ذهبي الكأس للفوز والرعاة، وخلفية رملية تشبه الساحات.

**الشعار النصي:** «ساحة — بطولات الحارة بمستوى المحترفين».

### الشعار (اللوغو)

- **الفكرة:** حرف «س» مرسوم كقوس منطقة الجزاء، ونقطة ذهبية فوقه تمثل الكرة، وبجانبه كلمة «ساحة» بخط Cairo بوزن 800.
- **النسخ:** شعار كامل (رمز + كلمة)، رمز وحده لأيقونة التطبيق (1024×1024 على خلفية خضراء)، ونسخة بيضاء للخلفيات الداكنة.
- **المساحة الحرة:** بعرض النقطة الذهبية من كل جهة، وأصغر حجم للرمز 24px.
- **تنفيذه:** ملف SVG يُرسم في أول جلسة برمجة داخل `packages/ui/assets`، ويمكن لمصمم تحسينه لاحقاً دون تغيير الكود.
- **المدرسة (المرحلة الثانية):** شعار درع ذهبي فيه رمز «ساحة» وتحته «المدرسة العراقية لتطوير المهارات الكروية»، بنفس الألوان والذهبي أساسي.

## هيكل المستودع وبيئة التشغيل

مستودع واحد اسمه `saha` في حساب abtkare، فيه ثلاثة تطبيقات وحزم مشتركة.

```text
saha/
├─ apps/
│  ├─ api/        NestJS — الخادم والـ API والمهام الخلفية
│  ├─ web/        Next.js — الموقع العام + لوحة الإدارة /admin
│  └─ mobile/     Expo — تطبيق آيفون وأندرويد
├─ packages/
│  ├─ shared/     أنواع البيانات ومخططات التحقق (zod) وثوابت الحالات
│  └─ ui/         الألوان والخطوط والشعار (tokens + assets)
├─ infra/
│  ├─ docker-compose.yml
│  ├─ Caddyfile
│  └─ sql/        audit_log.sql (تسلسل التجزئة والـ Triggers)
├─ .github/workflows/  بناء الصور ورفعها إلى GHCR
├─ docs/PLAN.md   نسخة من هذا المستند
└─ CLAUDE.md      قواعد المشروع لأي جلسة برمجة
```

**متغيرات البيئة (`.env`):**

| المتغير | مثال | الوظيفة |
| --- | --- | --- |
| `APP_URL` | `https://<IP>.sslip.io` | الرابط العام (يتغير عند ربط الدومين) |
| `API_URL` | `${APP_URL}/api` | رابط الخادم للتطبيق والموقع |
| `DATABASE_URL` | `postgresql://saha:***@db:5432/saha` | قاعدة البيانات |
| `REDIS_URL` | `redis://redis:6379` | المهام وRate Limit |
| `JWT_SECRET` / `JWT_REFRESH_SECRET` | نص عشوائي 64 حرفاً | جلسات الدخول |
| `AUDIT_HMAC_SECRET` | نص عشوائي | توقيع بصمة التدقيق اليومية |
| `OTP_PROVIDER` | `dev` ثم `sms` | مزوّد الرمز؛ في `dev` الرمز دائماً 000000 ويظهر في السجل |
| `STORAGE_DIR` | `/data/uploads` | مكان الصور على السيرفر |
| `ADMIN_EMAIL` / `ADMIN_INITIAL_PASSWORD` | — | أول مدير عام، يُغيّر بعد أول دخول مع تفعيل TOTP |
| `NOINDEX` | `true` | منع محركات البحث قبل الإطلاق |
| `HOST_HTTP_PORT` | يُحدد بعد الفحص | المنفذ على السيرفر |

**حاويات Docker:** `db` (postgres:16) · `redis` (redis:7) · `api` · `web` · `proxy` (Caddy). كلها باسم مشروع `saha` وشبكة `saha_net` منفصلة، ومجلدات بيانات باسم `saha_*`. المنفذ الوحيد المكشوف هو منفذ الـ proxy.

**قاعدة الـ proxy:** إذا كان المنفذان 80 و443 فارغين يعمل Caddy عليهما ويصدر شهادة HTTPS تلقائياً. وإذا كان هناك proxy قائم يخدم «خصوصي» و«مشاوي»، لا نشغّل Caddy، بل نضيف لـ `web` و`api` إعداد الانضمام إلى ذلك الـ proxy دون تعديل إعداداته الحالية. نتيجة الفحص تحسم هذا.

- **اللوحة `/admin`:** لوحة مؤشرات، البطولات والقرعة والجدولة، الفرق وطلبات التوثيق، المباريات والنتائج، الاعتراضات للجنة، الهيرو سلايدر، الرعاة وتقاريرهم، الأخبار والصفحات، المستخدمون والأدوار، سجل التدقيق مع زر «تحقق من السلسلة».

## خطة جلسات البرمجة

المرحلة الأولى مقسمة إلى 8 جلسات، كل جلسة تنتهي بملف zip قابل للرفع ونتيجة يمكن تجربتها.

| الجلسة | العمل | تُعدّ منتهية عندما |
| --- | --- | --- |
| 1. الأساس | هيكل المستودع، Docker، مخطط Prisma الكامل للمرحلة الأولى + SQL سجل التدقيق، بيانات تجريبية، الهوية (tokens وشعار SVG)، بناء تلقائي على GitHub، `CLAUDE.md` | النظام يعمل بأمر واحد، واختبار يثبت أن تعديل سجل تدقيق يُكتشف |
| 2. الدخول والأدوار | OTP، الجلسات، ولي الأمر، TOTP للإدارة، Rate Limit، مصفوفة الصلاحيات | اختبارات تثبت أن كل دور لا يصل إلا لما في المصفوفة |
| 3. البطولات والفرق | البطولات، التسجيل، القرعة، الجدولة، الترتيب، أحداث المباراة (`match_events`)، التوثيق اليدوي | بطولة تجريبية بـ 8 فرق تُنشأ وتُجدول ويُحسب ترتيبها صحيحاً |
| 4. النتائج والاعتراضات | حالات النتيجة، التأكيد المزدوج، انتهاء المهلة تلقائياً، لجنة الانضباط، الإشعارات | اختبارات لكل انتقال حالة، ونتيجة متنازع عليها لا تدخل الترتيب |
| 5. المحتوى والرعاة | الهيرو سلايدر، قياس الظهور والنقر، الأخبار والصفحات، بوابة الراعي | شريحة مدفوعة لا تُنشر دون اعتماد، والتقرير يطابق الأحداث |
| 6. الموقع واللوحة | كل صفحات الموقع العام واللوحة بالهوية | تعمل على الجوال والحاسوب باتجاه RTL سليم والوضع الداكن |
| 7. التطبيق | كل شاشات Expo والإشعارات | التطبيق يعمل على آيفونك عبر Expo Go من رابط مباشر |
| 8. النشر | التشغيل على الـ VPS برابط sslip.io، نسخ احتياطي يومي للقاعدة، نسخة TestFlight | الرابط يفتح بـ HTTPS و«خصوصي» و«مشاوي» تعملان كما هما |

**شروط تنطبق على كل جلسة:** لا أسرار داخل الكود (فقط `.env.example`)، اختبارات تمر قبل التسليم، كل النصوص بالعربية، وتحديث `docs/PLAN.md` بما تغيّر.

**قبل الجلسة 8 تحتاج:** حساب Apple Developer (اشتراك سنوي) وحساب Google Play Console (رسم مرة واحدة)، وحساب Expo مجاني. تحقق من الأسعار الحالية عند التسجيل.
